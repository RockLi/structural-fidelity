有限时域认证实现成本优化审计
2026-11-08

结论

保持原认证判据、数学包络、所有 guard 与理论边界不变，原生快速区间
筛选已显著降低原 Python/Fraction 实现成本；但公平的原生局部回放依然
更便宜。不能把优化后的结果表述为“认证比回放快”或新的仿真加速方法。
没有扩大网络实验，没有修改中英文论文或原复现包，也未开始独立验证。

1. 改了什么

(1) 用带向外舍入的 binary64 区间计算，确定原有理数公式投影到 binary32
    网格后的同一端点。无法确定时回退到原 Fraction 运算，不改变包络。
(2) 用等价的 IEEE 位操作实现相邻 binary64 数，减少 libm 调用。
(3) 共享输入准备缓存原图发放槽、每条边只做一次 weight*100，并向量化
    参考字段复制。目标顺序、源顺序、到达时间及事件存在性保持原样。
(4) 将认证和单点局部回放放在同一个 C 文件、同一编译选项下比较。
    本次是 Python 审计工具的原生计算内核优化，没有改动 Rust 模拟器。

2. 一致性结果

57 个原有案例逐项核对：
- 17 个“输入改变、脉冲不变”案例：仍为 16 个认证通过、1 个未认证。
- 4 个输入为零且状态相同的案例：仍全部通过。
- 36 个脉冲不同案例：仍没有认证通过。
- 99,696 个区间端点逐位相同；所有判断、未解决位置、原因、工作计数及
  最小 guard slack 与原实现、上一轮已存结果均相同。
- 所有优化后的输入数组逐位等于原准备方法。
- 原生局部回放全前缀逐位匹配独立 Python 回放；与候选闭环归档的比较
  限于第一次全局脉冲分歧之前，共检查14,461个目标-槽的三变量状态。
  分歧之后，参考驱动回放和闭环轨迹不再是同一个问题，不能强行比较。
- 第二个独立进程复跑上述全部案例，判定摘要与所有端点哈希完全相同。

唯一未认证案例仍为 swap93005__focal_burst：候选目标24在slot4开始
执行，参考在slot7才执行。认证要求执行分支一致，因此这项失败不等于
脉冲一定不同。未改变判据来提高16/17覆盖率。

补充算术测试覆盖40,026次相邻binary64数检查，以及1,440次三类运算
与有理数 oracle 的端点比较；三类精确回退各强制执行240次，另覆盖一次
自然触发的回退。实际57案例没有调用回退，但不能外推未来回退率。

3. 公平成本比较

主表采用16个完整通过的非零扰动案例；两种方法都检查两个受影响目标、
完整300槽，避免早停工作量不同。表中是案例间中位数，单位毫秒。
每次内核计时采用11轮、每轮100次C内批处理，对称预热、交替次序，均
不输出状态轨迹；共享准备与图读取各计时3次。保留全部逐例逐轮读数。

                                 第一次进程             第二次进程
原生认证内核                       0.13115                0.13411
原生单点局部回放内核               0.003430               0.003458
认证 / 回放内核配对比值中位数      38.72倍                 38.84倍
共享内存输入准备                   0.45306                0.44131
输入准备 + 认证                    0.57597                0.56291
输入准备 + 回放                    0.45652                0.44442
图CSV读取与支持集差分              4.24025                4.25187
图处理 + 输入准备 + 认证           4.84071                4.80904
图处理 + 输入准备 + 回放           4.70755                4.68727

“合计”先在各案例内相加，再对案例取中位数，所以不必等于表中其他中位数
的直接相加。合计是组件计时组合，不是部署环境完整请求延迟测量。磁盘读
受到操作系统缓存影响。完整参考载入、重建检查和源活动索引另有一次性
成本：首次进程三种输入分别0.684、1.121、0.642秒；两种方法共同需要，
不计入每个候选的表中，也不能在一次性应用中忽略它。

原Python有理数实现同轮重测中位数73.679ms（复跑71.100ms），包含它
自己的输入准备及验证轨迹构建；新版输入准备加认证约0.576ms。逐例比值
中位数约124.5倍（复跑122.8倍）。这是实现替换的成本改善，旧版额外
构建轨迹且语言不同，不能把这个数字当作算法比局部回放快的证据。

全57案例与目标17案例的汇总均在results/summary.json和repeat下完整
保留。未认证例可能早停，比较内核的主要结论采用上述完整通过16例。
原生认证和原生单点局部回放各有20例通过；它也不是免费或无需原图的预测器。

本机环境：Apple arm64 Darwin，Apple clang21.0.0；编译选项
-O3 -std=c11 -fno-fast-math -ffp-contract=off；Python3.13.5、NumPy2.5.4。
完整操作系统版本及源代码哈希见每次summary.json/code-sha256.json。

4. 理论边界没有扩大

认证仍只针对固定原图参考、固定候选图、固定初值/输入、固定binary32
执行规则及300槽窗口，保留相同的阈值/不应期/调度分支。内部连续状态可
不同。失败仍是未认证。不能推及其他输入、其他图族、未来时间、不同
浮点后端、模型真实性或参数扰动族。计算包含候选受影响目标的事件访问，
未消除邻接访问，也未减少原图参考获取成本。

单点局部回放在同一执行契约下，也可以通过逐目标条件回放与归纳确定
具体候选的分支和脉冲一致。不能用“认证有理论保证，回放只是经验比较”
来回避成本结果。区间方法额外显式生成状态包络，但本次没有证明它能以
一次运行覆盖新参数族、未见输入或不确定性范围。

5. 下一步判断

工程可行性通过：原实现的解释器/有理数开销已不是主要障碍。成本优势
未通过：若目标只是对一个给定候选确认有限窗脉冲和分支一致，当前应优先
使用更便宜的局部回放。不能仅凭本次优化把认证升级为独立论文的新卖点。

因此不建议以“认证代替回放省算力”为理由立即扩大独立验证。先保留这版
为精确判据审计与状态包络工具。若后续研究需要一次认证覆盖一族明确的
参数不确定性、或可独立检查的包络证书，再先定义单点回放无法同价提供的
交付目标，然后决定新的独立验证。这里没有执行这些新增研究。
